# Backup certs/accounts

Pulls every app's *active* ACME cert — account keys, certificate, and chain files — from
`root@ertrzyiks.me`'s Dokku apps down to a local Mac, so there's an off-server backup if the host
is ever lost or rebuilt.

Each app's ACME data lives at `$DOKKU_ROOT/<app>/letsencrypt/certs/<hash>/...` on the remote host,
where `<hash>` is generated by the ACME client and a new one is created on every renewal — `certs/`
accumulates one hash directory per past order, with a `current` symlink pointing at whichever one
is presently active. The script discovers every app under `$DOKKU_ROOT` (default `/home/dokku`)
that has a `letsencrypt/` folder, resolves each app's `certs/current` symlink, and backs up only
that target directory — not the full renewal history, which just accumulates expired/superseded
certs with no recovery value. An app with no resolvable `certs/current` (e.g. letsencrypt not
enabled for it) is skipped, not treated as a failure.

Run this locally on your Mac, not in CI or any sandbox — it needs real SSH access to the
production host and writes its output to your home directory.

## Requirements

- Passwordless SSH access to `root@ertrzyiks.me` (key-based auth via `ssh-agent`, or a key
  referenced in `~/.ssh/config`). The script uses `BatchMode=yes`, so if auth isn't already keyed
  up it fails fast with a clear error instead of hanging on a password prompt.
- `rsync` (ships with macOS).

## Usage

```bash
./backup-certs-accounts.sh
```

Each run creates a timestamped snapshot under `~/Backups/dokku-letsencrypt/<timestamp>/`, one
subfolder per discovered app (e.g. `home/letsencrypt/`, `blog/letsencrypt/`), and repoints a
`latest` symlink at it — but only if every app backed up successfully; if any app fails, `latest`
is left pointing at the prior successful snapshot so a partial run never gets treated as the
current backup. Unchanged files are hard-linked against the previous snapshot per app (via
`rsync --link-dest`), so disk usage only grows with what actually changed between runs.

A per-run log is written to `~/Backups/dokku-letsencrypt/.logs/<timestamp>.log`.

## Notes

- This backs up **private keys and account credentials**, not just config — treat
  `~/Backups/dokku-letsencrypt` on your Mac accordingly (it inherits your normal user's file
  permissions, not root's).
- `rsync -a` preserves ownership/group only when run as root locally; since the script runs as
  your normal Mac user, expect (harmless) ownership-preservation warnings in the log — content and
  permissions still copy correctly.
- If `$DOKKU_ROOT` differs from `/home/dokku` on your host, edit the `DOKKU_ROOT` variable at the
  top of the script.
- Not part of the `apps/*` pnpm workspace and not deployed anywhere; a standalone operational
  script you run by hand when you want a fresh backup.
